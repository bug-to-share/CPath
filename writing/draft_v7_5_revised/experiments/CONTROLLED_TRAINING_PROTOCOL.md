# Limited controlled training comparison

Protocol fixed on 2026-11-04 before training these configurations. This is a supplementary comparison, not a replacement for the historical model or a search for significance.

- **Question:** Does the model configuration show consistent behavior across three training seeds when the split, training bags, order, optimization and evaluation inputs are controlled?
- **Runs:** 3 configurations × seeds 17, 29, 43 = 9 runs. All completed, failed or negative runs will be retained. No additional seeds will be selected on performance.
- **Configurations:** (1) matched attention: the same 1536→256 projection, same gated attention block and same 256-input classification head as Hybrid; (2) full concatenation with each of the five branch vectors multiplied by 0.2, retaining the eight statistics and fusion layer; (3) original learned-gate full model. Matched attention omits the other features, eight statistics and fusion layer; it is not parameter-matched. Fixed versus learned scaling also changes nonlinear capacity. These comparisons do not isolate each branch or causal adaptation.
- **Initializations:** For each seed create one fresh full model. Shared tensors are copied identically into all configurations. The constant gate has no trainable parameters. No historical checkpoint is used to initialize training.
- **Fixed inputs:** Reuse the original 144/49 training/evaluation split. Freeze original internal evaluation bags (42 + original evaluation-row index, sorted indices for >=512 rows). Use original external Hybrid reference bags for the 168-slide external set. External results are computed only after checkpoint selection and do not affect training or checkpoint choice.
- **Training sampling:** 512 rows per slide, without replacement when possible, otherwise with replacement. For each training seed and epoch, derive a 32-bit seed using the first four little-endian bytes of SHA256(`controlled-v6|seed|epoch|study_slide_id`). Sort indices when >=512 rows. Identical training bags and minibatch orders are used for the three configurations within each seed. Order RNG: first four bytes SHA256(`controlled-v6|seed|epoch|order`). Save exact training indices and orders.
- **Optimization:** 30 epochs for every run, batch size 8, AdamW lr=5e-5, weight_decay=1e-4, dropout=0.3, positive BCE weight=77/67, no scheduler, no calibration, no early stopping. Select the first epoch with strictly highest internal AUROC, following the established model-selection convention. Also retain final-epoch weights and metrics.
- **Randomness:** Reset PyTorch batch RNG to SHA256(`controlled-v6|seed|epoch|batch_index|dropout`) for each batch. Common execution prefixes therefore have aligned randomness; dropout draws after differing graph branches are not guaranteed to be elementwise paired. Enforce deterministic algorithms and record software, CUDA, hardware and hashes. Seeds quantify training variation in this fixed cohort, not extra independent clinical observations.
- **Reporting:** Each seed's selected epoch, internal/external scores, AUROC, sensitivity/specificity and parameter count; paired per-seed differences and mean ± sample SD. Three seeds are not used as a substitute for clinical sample size or for an inferential significance claim. Threshold fixed at 0.5. Original ABMIL and its historical results remain separate.
- **Compute:** Physical GPU 3 only. Cached existing UNI2-h features; no new feature extraction and no changes to original files or checkpoints.
